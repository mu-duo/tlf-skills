# 课程

按一个顺序构建产物：`spine.md` → `graph.yml` → 概念页 → `cheatsheet.md`。在概念图谱之前写概念页，得到的是一页没有前置、在路径中没有位置的内容；它要么被重写，要么成为孤儿。

上限就是上限。如果某份产物放不下，是内容范围错了：拆分概念、拆分产物，或把细节下沉到更低的层。绝不压缩行文来凑数。

## `spine.md` —— 整个领域，粗略版

上限：800 词。在 `start` 时写一次，仅在概念图谱证明它错了时修订。

`../SKILL.md` §5 中的六个部分，按该顺序作为标题。读者必须能在一次坐下中把六个部分都记住；这就是全部的检验。

| # | 标题 | 内容 | 长度 |
| --- | --- | --- | --- |
| 1 | 一句话 | 这个领域回答什么问题，为谁，靠什么手段 | 1–3 句 |
| 2 | 边界 | 内部 / 相邻 / 假定且从不质疑 | ≤180 词 |
| 3 | 核心回路 | 一个典型从业者任务，5–7 个编号步骤，端到端 | ≤200 词 |
| 4 | 名词 | 5–8 个实体，各一行，以及它们之间的关系 | ≤180 词 |
| 5 | 接缝 | 领域在哪里被切成子领域、学派或方法；什么穿过每个切口 | ≤150 词 |
| 6 | 刻意不覆盖 | 标准教材有意忽略什么，以及因此显得奇怪的是什么 | ≤150 词 |

第 6 部分不是可选项，也不是免责声明。它是这个领域的结论为何成立、失败为何可预测的原因。缺少这一部分的用户会把模型用到领域之外，并自信地犯错——这比不知道更糟。

随包模板（`assets/spine.template.md`）把第 2–6 部分各渲染成一张表——边界：内部 / 相邻 / 假定；名词：实体 / 它是什么 / 关联到 / 来源；接缝：接缝 / 什么穿过 / 两侧各自承诺什么；省略：忽略什么 / 为何 / 什么显得奇怪——再加一行收尾「这份总纲压平了什么」。下面的示例为了密度写成散文；字段相同。核心回路的每一步都要带 `verified` / `inferred` 标记。

### 完整示例 —— 精品咖啡冲煮

不是目录。没有历史，没有器材评测。

**1. 一句话。** 这个领域回答：给定固定质量的咖啡粉和水，你如何改变你能控制的变量，使一杯咖啡可复现而不是靠运气——对象是在家冲煮的人，或在咖啡馆调参的咖啡师。

**2. 边界。**
内部：萃取、水质化学、研磨分布、粉水比、温度、时间，以及闭合回路所需的感官判断。
相邻：生豆农业与烘焙（它们设定输入；本领域把豆子当作给定条件）、设备工程、咖啡馆运营。
假定且从不质疑：目标风味可以被描述并复现；折射仪或受过训练的味觉是有效仪器；「更好」意味着萃取更均匀，而不是更浓。

**3. 核心回路。** （1）固定一份配方：粉量、水量、温度、研磨刻度。（2）冲煮，并对接触时间计时。（3）测量：液量、时间，以及 TDS 或味觉。（4）与目标比较。（5）改变**一个**变量——通常是研磨。（6）重新冲煮。（7）记录命中目标的设置，因为下一袋豆子还会需要它。

**4. 名词。** *萃取率*（溶解出来的量占粉量的比例）；*TDS*（杯中的浓度）；*粉水比*（粉量对水量）；*研磨分布*（颗粒尺寸的分布，不是平均值）；*水硬度/碱度*（水带来了什么）；*均匀度*（上述六者的关系）。关系：粉水比与萃取共同决定 TDS；研磨同时改变速率和均匀度；水质化学决定到底能萃出什么。

**5. 接缝。** 浸泡 vs 渗滤（什么携带可溶物：静置的液体还是流动）；意式 vs 手冲（压力改变的是机制，不只是浓度）；感官 vs 仪器评估（味觉 vs 折射仪，它们在最边缘处会不一致）。每个切口穿过什么：同一个萃取模型，只是时间常数不同。

**6. 刻意不覆盖。** 咖啡因药理、牛奶与糖浆、咖啡馆经济、豆子产地。奇怪的后果：这个领域谈论「平衡」时仿佛它可以被测量，而它确实可以——粗略地，由两台彼此相差零点几的仪器测量。从未见过这个省略的用户，会把折射仪读数当作事实基准。

### 总纲中应当省略什么

- 单个概念的定义——那是概念页的事。
- 历史、人名、日期，以及谁发明了什么。
- 带数字的完整示例。
- 工具与厂商对比。
- `[s1]` 风格 id 之外的来源引用；总纲是模型，不是书目。
- 超出第 5 部分一个从句的争议；真正的分歧会得到一个概念节点。

总纲要声明自己的简化。用一行话结束第 6 部分，点名总纲压平了什么。

## `graph.yml` —— 骨架

机器可读的状态，不含散文（schema 见 `artifacts.md`）。由总纲构建，不是由教科书的目录构建。

### 寻找节点

来源，按顺序：

1. **名词**（5–8 个）和**核心回路**的步骤——这些几乎总是节点。
2. **接缝**——每个交叉通常是一个节点或一种边类型。
3. 用户命名的**能力**——把它分解为从业者需要的概念，从结果倒推。
4. 来源的章节目录作为**检查清单**，不是照抄。如果某一章没有对应节点，问：是领域忽略了它，还是概念图谱漏了它。

第一遍目标为 **12–40** 个概念。

| 数量 | 解读 |
| --- | --- |
| < 10 | 太粗，无法教学；很可能是单个技能，不是领域（`../SKILL.md` §2） |
| 12–40 | 第一遍合适 |
| > 40 | 是目录，不是模型——合并同类节点 |

后续轮次在页面被拆分处增加节点。增长是正常的；第一遍 40 个节点、两个月后到 55 个是健康的。

### 边类型

四种，没有其他。每条边读作 `from → to`。

| 类型 | 读作 | 影响层级 | 示例 |
| --- | --- | --- | --- |
| `prerequisite` | 「要掌握 `to`，必须先掌握 `from`」 | **是**——唯一影响层级的类型 | `brew-ratio → extraction-yield` |
| `composes` | 「`from` 由 `to` 组成」（整体 → 部分） | 否 | `espresso-brewing → puck-preparation` |
| `contrasts` | 「`from` 与 `to` 是替代方案，或常被混淆」 | 否 | `immersion → percolation` |
| `applies` | 「`from` 被应用在 `to` 之中」 | 否 | `refractometry → dialling-in` |

规则：

- `contrasts` 边**只存一次**。方向：低层级 → 高层级；同层级则按 `from` 字母序。
- `composes` 在层级计算中不可传递。部分不自动是前置；如果它确实是，就同时加上 `prerequisite` 边，并在会话记录中说明理由。
- `applies` 是方法与仪器进入概念图谱的方式。它把它们挡在前置链之外，否则它们会错误地卡住理论。
- 环路是建模错误，绝不是要保留的怪癖。合并节点，或把一条边降为 `contrasts` / `applies`。

### 稳定的 id

- ASCII、kebab-case，由规范英文名派生：`extraction-yield`、`water-alkalinity`。
- **首次写入后绝不重命名。** 重命名会破坏会话记录、证据链，以及用户手工建立的任何链接。同义词放进 `aliases`。
- 真正的拆分创建新 id；旧 id 保留其证据，并增加一条指向新节点的 `composes` 或 `prerequisite` 边。
- 冲突用消歧后缀，不用数字：`elasticity-price`、`elasticity-substitution`。

### 一行规则

`one_line` 用一句话描述这个概念，≤15 词，描述它**做什么**，而不是它叫什么。

- 最多一个关系，不许有「和」。如果这一行需要「和」，这个概念就是两个节点。
- 不复述名称：「萃取率——溶入杯中的咖啡质量占比」是定义；「决定粉量中有多少进入杯中，因而在给定粉水比下确定浓度」才是一行简介。
- 它同时是页面的第一行，逐字相同，也是层级扫描唯一加载的内容。为扫描而写。

### 层级分配

按前置闭包机械分配：

```
tier(c) = 1                                  if c has no prerequisite
tier(c) = min(4, max(tier(p) for p in prereqs(c)) + 1)
```

按依赖顺序计算；有层级 3 前置的概念至少是层级 4，并做上限截断。然后把结果对照 `../SKILL.md` §7 的层级定义检查：

| 层级 | 英文 | 用它检验分配结果 |
| --- | --- | --- |
| 1 | Novice | 能用词汇和一个关系讲清 |
| 2 | Beginner | 能从完整示例复现 |
| 3 | Practitioner | 需要为新案例在方法之间做选择 |
| 4 | Adept | 需要边界与代价，且能教给别人 |

如果算术把它放进层级 4，但它没有任何边界或代价，那它是一个话题，不是概念。拆分它或丢掉它。如果概念落在层级 1，却无法只用词汇解释，说明缺一条前置边——在写页面之前找到它。

绝不手工分配层级来让图谱看起来均衡。算术是契约；一个层级 4 为空的四层图谱是诚实的，注水的不是。

`tier_current` 是另一个数字，位于 `graph.yml` 顶部：用户已被**晋级进入**的层级。它在 `start` 时写为 `1`，只由一次晋级的 `exam` 递增，绝不根据概念等级重算。概念的 `tier` 与用户的 `tier_current` 合理地会漂移——用户可能处在 `tier_current: 2`，而某些层级 3 的概念已因零散阅读停在 L1。绝不要通过编辑任一字段来「修正」这种漂移。

### 去重与合并

以下任一为真时合并：

- 一个问题可以同时回答两者。
- 一个是另一个的特例**且**失效模式相同。
- 二者只有词汇差异（学派术语、翻译）。

特例具有**不同的失效模式或不同的代价**时不要合并——那个差异正是节点存在的理由。

合并流程：保留边更多的 id；把另一个的 id 与名称移入 `aliases`；保留更强的 `one_line`；取 `max(level)` 并保留**全部**证据；合并 `sources`；重接边；在会话记录中写明合并及其理由。绝不为了整理图谱而删除证据。

## 选择算法

只定义一次，在 `session-loop.md` → `learn`。不要在 `learn`、`drill` 或 `cheat` 中临时换一个顺序：排期是让学习库成为一条路径的唯一东西。

简版，用于图谱正在构建、任何页面都还不存在时就必须选出下一个概念：

1. 只看 `graph.yml:tier_current` 所在层级。候选是 `L0` 且没有证据的概念。
2. 只有当每个前置祖先都是 `L1` 或以上时，候选才就绪。
3. 在就绪候选中取 `tiers[].concepts` 顺序里的第一个——该顺序是人工编排的，不是字母序。
4. 没有候选：取该层级中等级最低的概念（并列时：校准误差最高，再取最早的 `next_review`）。
5. 全部为 `L2+` 且门槛通过：建议 `exam`；不要开启下一层级。

含失败处理的长版是规范版本。

## 概念页

上限：**400 词**。一页，一个概念。

```markdown
# Extraction yield

> <one_line from graph.yml, verbatim>

## What it is
2–4 sentences: the claim itself, terms defined on first use.

## Why it sits here

- Prerequisites: `brew-ratio` — what must already be in place, and why
- Dependents: `grind-distribution` — what cannot be understood until this is
- Tier: 2 (Beginner) — the milestone this concept serves

## Mechanism / rules

1. <rule> (verified)
2. <rule> (inferred)
3. <rule> (inferred)

**When it holds:** conditions; the failure when pushed past them; what using it costs. (verified)

## Worked example
One concrete case: steps and outcome, not a derivation.

## Common misconceptions
- <the belief a learner actually holds> — <what is wrong, one-sentence correction>

## Self-test
> <one question not answerable by recalling the page's wording>

## Sources
- `s1` ch. 4 — which claim this supports (verified)
- analogy to pressure drop — which claim (inferred)

<!-- Deliberately leaves out: <the simplification contract>. -->
```

`assets/concept.template.md` 是规范副本；上面的标题就是它的标题，顺序不可更改。

困难之处：

- **引用块 = `one_line`。** 除 `>` 标记外逐字节相同。对六十页做层级扫描依赖这一点。
- **写关系，不写事实。** **Why it sits here** 必须与 `graph.yml` 的边一致：前置、后继、层级。如果某个前置还没有页面，写「尚未写就」——不要悄悄丢掉这个链接。
- **「When it holds」是强制的。** 没有条件的论断无法用到新案例上，因此无法达到 L3。
- **结尾注释是强制的。** 渐进细化，不是披露（`../SKILL.md` §6）。
- **400 词是整页**，包含完整示例。一个案例，不推导，至多 2 个公式，且仅当关系无法用文字陈述时。
- **一个误解对应一个真实信念。** 编造的误解是教错东西的考题素材。

### 好页面（压缩版）

> **萃取率。** *决定粉量中有多少进入杯中，因而在给定粉水比下确定浓度。*
> 它是什么：咖啡溶解了多少——区分「浓」与「苦」的那个数字。
> 机制：水先溶解表面化合物，再触及细胞壁；更细的研磨缩短路径，但拉宽分布。萃取率 = 溶解质量 / 粉量。（inferred）
> 何时成立：粉床被均匀浸润，且水温在配方的温度带内。超过约 22% 后苦味化合物占主导，模型仍能预测，但那一杯已不再被需要。
> 不覆盖：「苦」在化学上是什么，以及压力驱动的流动。

### 坏页面（不要写成这样）

> **萃取率。** 萃取率是咖啡中的一个关键概念。历史上，咖啡科学在 20 世纪随 SCA、Lockhart 等人的贡献发展而来。存在若干定义：SCA 定义、「冲煮控制图」定义，以及由折射仪导出的定义。TDS 用折射仪测量，它利用折射率。许多因素影响萃取：研磨、温度、时间、比例、水、搅动、压力、粉碗形状。萃取可以用多种方式测量。理解萃取率对做出好咖啡很重要。

为何失败：没有机制、没有条件、没有代价、没有可用于新案例的关系；用历史和名代替模型；在该有箭头的地方给了一张未定义的列表；它教的是「掌握词汇就是目标」。它还在内容少于好页面的情况下超出上限。任何评分者读它都只能给 L1。

### 概念页上的刻意不覆盖

省略：领域历史、其他概念的机制、完整推导、工具评测、考题式完整示例，以及任何已在前置页面上的内容。用一行说明省略，而不是假装页面已经完整。

## `cheatsheet.md` —— 一页

最后构建，来自 L1+ 的概念页，绝不只来自总纲（`session-loop.md` → `cheat`）。

```markdown
# <Field> — cheat sheet

> **<one line: what this field gives you>**

## Core rules, formulas, and steps
- **<rule>** — <when it applies; one condition>
- **<step sequence>** — <the order, and where it breaks>

## One table or diagram
| <input / case> | <output / result> | <when not to use it> |
| --- | --- | --- |
| <case> | <result> | <boundary> |

## Concrete examples
1. <one-line case> — <the result, and the rule it exercises>

## Pitfalls
- <the mistake that looks correct> — <the tell, and the fix>

## Pre-use checklist
- [ ] <condition confirmed before starting>

## Quick recall
1. <question answered in one line>
```

`assets/cheatsheet.template.md` 是规范副本。规则：每项一行；规则按 `spine.md` 的核心回路排序，不按字母序；表格由 `contrasts` / `applies` 边构建，只有在表格无法承载任何内容时才可以省略；陷阱是记录下来的误解，逐字照录；不要成段散文；一页打印（把约 45 行当作预算）。任何需要一段话的东西都属于概念页。

## 存在竞争学派的领域

领域可能包含真正的分歧——两种方法、两个定义、两个传统。规则：

1. **一个领域，一个基础模型。** 选用户情境所用的学派；如果没有，选来源视为当前主流的那个，并用一行说明理由。
2. **分歧是一个节点**，不是两套并行课程。id 形如 `schools-of-<x>` 或 `<x>-measurement-dispute`，放在该分歧首次改变答案的层级。
3. **另一学派在该节点内得到一个别名和一行说明**，外加一条指向基础概念的 `contrasts` 边——不给它独立页面，除非它有自己的前置。如果它有，那就是另一个领域，拥有自己的领域目录（`../SKILL.md` §3）。
4. **绝不在一次坐中考查两个学派的词汇。** 闯关考考查基础模型，以及说出另一学派主张什么、领域当前为何偏向其一的能力（`sources.md` → 冲突处理）。
5. 该节点的 **When it holds** 一节说明什么证据能了结争议。这是「我们还不知道」的诚实形式。

## 按产物划分的刻意不覆盖

| 产物 | 刻意省略 | 因为 |
| --- | --- | --- |
| `spine.md` | 概念定义、历史、数字、工具对比 | 它是模型，不是摘要 |
| `graph.yml` | 散文、理由、按重要性排序 | 它是状态；散文最先过时 |
| `concepts/<id>.md` | 其他概念的机制、推导、考题式答案 | 400 词是一个加载单位 |
| `cheatsheet.md` | L1 以下的一切、任何需要一段话的东西 | 它是压缩后的回忆 |
| `sources.md` | 第五个来源之后的一切 | 精选胜过收集 |
| `README.md` | 任何无法从 `graph.yml` 推导的事实 | 它是缓存 |
