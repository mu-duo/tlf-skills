## 背景与目标

用户批准了新的安装语义。README 此前描述的与之相反：同名路径默认受保护、`--force` 只覆盖主 skill、依赖永不覆盖。目标：安装器与 README 一致地表达并实现「普通安装对第一方 skill 全目录同步；无法确认为包内安装的第一方路径默认保留、`--force` 才替换；外部依赖始终保留」的语义。

- **不**改 `skills/**`；**不**记录任何未批准的新政策；**不**做 project init；skill 不被自动调用；无测试治理 / 渲染器改动。

## 方案（简述）

- 普通安装对第一方 skill（`project-docs-workflow`、`doc-opt`、`docs-html-view`）执行**全目录同步**：仅当上一份**有效清单**确认该路径由本包安装（`installed` / `forced`、本地）时覆盖——**可覆盖本地修改**；受管第一方目录是可整体替换的分发副本。
- 无法被有效清单确认的第一方路径（手工复制 / `skipped` / 清单缺失 / 清单损坏不可解析 / 符号链接）默认**保留**；`--force` 显式替换该第一方条目（替换路径本身，符号链接 referent 不变）。
- **外部依赖 skill 始终保留**（含 `--force`）；`--with-matt-skills` 只补**缺失**的上游名称；缺失的轻量 / 上游依赖按既有行为补装。
- 主 skill 的内部引用（`references/deps/*`）随主 skill 更新，不当作独立外部依赖单独管理。
- 版本选择：不带版本时 `npx` 可能**优先使用当前项目已安装的版本**；显式 `@latest` / `@<版本>` 选择安装器版本（缓存 / 网络策略另计）。安装器不自取版本。**兼容性限定**：`npx <pkg>@<版本> install` 运行该版本自带的安装器代码，上述自动同步 / `--force` 语义**仅适用于包含本安装策略的包版本**；更早的已发布版本保留其历史行为（如 `--force` 可能只覆盖主 skill），故「较旧版本回滚」仅在此类兼容版本内成立。不新增 `--source` / 网络 / `update` 命令。
- 目标 / 预览：`--dir`、`--dry-run`（无写入、精确动作）。
- 安装只处理 skills 目录；不触碰目标项目已物化文档（`AGENTS.md`、`docs/agents/*` 等），需显式对齐 / 迁移。
- 清单文件本身是符号链接时始终拒绝（即使 `--force`）；单 skill 替换失败恢复旧内容或保留备份并报告路径，非全局事务。
- 卸载清单语义不变；清单不记录本地改动指纹。
- 不新增命令（无 `update`）；不宣称所有 skill 的事务原子。
