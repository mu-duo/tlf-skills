# ADR 约定

默认方案。项目可在物化的 `docs/adr/README.md` 中覆盖；该副本决定运行时行为。

## 文件

- 文件名 `NNNN-slug.md`：4 位零填充。**编号永不复用**——新条目取当前最大编号 + 1（墓碑桩计入）。H1 标题使用项目语言。
- slug（文件名）**不可变**：墓碑桩化只清空正文，绝不重命名文件。
- 编号竞争：新增时若编号已被占用（并发写入），顺延 +1 并核查引用（见「引用核查」）。

## 生命周期

ADR 集合保留当前条目加退役标记行；允许修改和删除。完整历史由 git 承载。

- **语义修改**（结论 / 约束 / 范围）：就地修改，并向 `## Log` 追加一行——`- YYYY-MM-DD <一句话原因>`（规范格式：日期在前、原因在后，不加前缀标签）。
- **非语义修改**（错字、格式、链接）：直接修改，无需 Log。
- 默认就地修改。仅当变更具有方向性、或值得长期单独引用时，才写**新** ADR；随后为旧条目加注记（见「注记」）。

## 删除

- 优先使用注记：`> 已废弃（日期）：原因` 保留内容。仅当项目的**人类 owner**（或经其明确授权者）判定该条目无参考价值 / 纯属噪音时才删除——agent 不得自行决定删除。
- 删除 = **墓碑桩**：将文件正文清空为两行——`# <原标题>` 与 `> 已删除（YYYY-MM-DD）：原因`——保留编号和文件名（现有路径链接仍然有效）。
- **墓碑桩是终态**：墓碑桩永不再删除；编号永久退役。
- 删除顺序：① 将文件墓碑桩化（改写正文）→ ② 从目录中移除该行 → ③ 执行全仓库引用核查。重试 / 重跑前先核对，避免重复 Log 行或注记。

## 注记

状态块位于 H1 之后的前几行。活跃条目不带注记。退役条目**只携带下列固定集合中的标记行**——每个退役事件一行，可叠加；不允许自由文本注记：

| 标记 | 含义 |
| --- | --- |
| `> 已被 ADR-XXXX 取代（日期）：原因` | 已被更新的 ADR 取代（写了新条目） |
| `> 经 ADR-XXXX 修订（日期）：说明` | 已被更新的 ADR 就地修订 |
| `> 已废弃（日期）：原因` | 已废弃；内容保留 |
| `> 已删除（日期）：原因` | 已删除；墓碑桩 |

## 引用核查

`ADR-XXXX`（4 位零填充）是原生引用写法。PRD / Current 也可以用**稳定的 Markdown 路径**链接 ADR——例如 `支持[离线使用](../../adr/0003-offline.md)`，可带 `#fragment`；此时描述性短语承载含义，因此链接处不需要 `ADR-XXXX` 标签。两种写法都有效；这不改变 ADR 生命周期（见 `rendering.md`）。

每当条目**被删除或被语义修改**，执行者必须核查引用：优先派 subagent；没有则直接 grep。核查**两种写法**——`ADR-\d{4}` 编号，以及按稳定文件名模式 `adr/<NNNN>-<slug>.md` 指向 ADR 文件的 Markdown 链接（任意相对前缀——`docs/adr/…`、`../adr/…`、`../../adr/…`，可带或不带 `#fragment`）。范围 = 整个仓库（`docs/` 必须更新；代码注释逐条判断：保留 / 更新 / 就地注释）。处理完每个命中项后再收尾。当引用指向已删除条目时，优先改指替代 ADR 编号；无替代则删去该句，或就地注明 `(ADR-XXXX deleted)`。

路径链接在墓碑桩化后仍然存在（文件名不可变），且墓碑桩照常渲染，因此这类链接仍可解析——但**语义**修改会改变链接所指的内容，因此要重新阅读并审查每个路径链接引用，而不只是编号。

## 索引（README）

`docs/adr/README.md` 是**目录**，不是状态权威：表格 `| 编号 | 标题 | 一句话 |`。它列出每个**未删除**的条目——包括带退役标记的条目；删除会移除该行，编号出现空缺表示已删除（见对应的墓碑桩 / git）。「一句话」列可注明退役条目的状态（例如「已被 ADR-XXXX 取代」）。其规则章节陈述本 v2 生命周期。新增条目后，在目录中登记一行。

## 正文形态

H1 标题 → 决策 + 理由 + 权衡（`代价：…`）→ 可选的 `## Log`（每次语义修改时追加）。默认不设 `## Considered Options` 章节；`代价` 指所选方案承担的代价。

一条 ADR 可以只有一段；价值在于记录*做出过*某项决策以及*为什么*。

## 否定决策

默认：记录已采纳的决策，而非被拒备选方案。不要添加 `## Considered Options` 章节。只有当提及某个被拒备选方案能防止可预见的重复讨论，或审计 / 合规明确要求时，才可用一句话提及；绝不要罗列备选方案。默认由 agent 判断「防止重复讨论」这一例外；用户 / 项目可以覆盖。`代价：…` 描述所选方案的代价，而不是被拒方案。既有条目是历史：不要改写；用户可显式授权清理。本策略只约束持久记录；对齐 / `grilling` 仍可探索备选方案。PRD 的非目标 / out-of-scope 陈述是范围边界，不是被拒备选方案；保留它们，无需逐条理由。

## 与 domain-modeling 的关系

基础 ADR 格式与 `domain-modeling` skill 的 ADR-FORMAT 兼容（未安装则按 `references/deps/domain-modeling.md` 执行）。该 skill 既不禁止修改也不禁止删除，并带有自己的 `proposed | accepted | deprecated | superseded` 状态词；本方案是其超集（引用核查、墓碑桩、目录式 README），两者共存。基础格式把 `Considered Options` 列为可选章节；本方案默认省略（见 `## 否定决策`）。见 `coexistence.md`。
