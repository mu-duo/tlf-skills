# 内置：边界类能力（deepwork / retro / improve-codebase-architecture）

> 该能力的唯一来源，按对应小节执行，不调用外部 skill。

## deepwork

**什么时候**：一块工作跨多个阶段，且每一步都含不可逆或高成本的决定。

**怎么做**：切成阶段，每阶段写明进入条件与退出证据；每阶段结束停下来评审，通过才进下一阶段。计划 → 实现 → 评审 → 下一阶段。

**边界**：与 `project-docs-workflow` 的五步流程互斥。同一个 effort 只选一个，不叠加。

## retro

**什么时候**：一段工作结束后，想改善 agent 的工作方式——不是改项目文档。

**怎么做**：三问。

1. **发生了什么**：读会话原始记录；未指定则用当前会话。
2. **什么有效**：值得保留的做法、配置、提示。
3. **改什么**：只提作用于 agent 环境的改进候选（导航指针、自动化检查、规范约束、指令瘦身、工具成本、信息可达性），按影响排序，交给用户定。

**边界**：`project-docs-workflow` 第五步只做文档同步，复盘不在那里做。

## improve-codebase-architecture

**什么时候**：想在不动行为的前提下改善模块结构，让它更好测、更好被 agent 读懂。

**怎么做**：先找「浅模块」——接口比实现复杂、调用方必须知道太多细节；再讨论把它变深的切口：收窄接口、隐藏实现、把变化关在内部。

**范围**：本包不提供扫描、评分或报告流程；需要术语或决策记录时，按同目录 `domain-modeling.md` 执行。

## doc-opt

默认来源是同目录 `doc-opt.md`；完整版随包提供于 `skills/doc-opt`，仅在用户显式要求时使用。
