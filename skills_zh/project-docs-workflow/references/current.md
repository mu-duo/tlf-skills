# Current 现状文档

Current = 产品**当前实际建成**的形态：实际能力、关键行为与限制，均相对项目选定的基线陈述。它是 PRD（宏观产品叙事）与 SPEC（实现事实标准）旁边的实际建成快照。与 PRD 平级的树（`prd.md`），不是其章节。默认方案；可在项目副本中覆盖。Current 在发布范围内，与 PRD、SPEC 附录一起发布（`rendering.md`）。

**PRD 不含状态；Current 是唯一的状态来源。** PRD 叙述目标，不承载进展、状态标记或实际建成声明。任何「现在实际能做什么」都从这里读。

## 结构

- `docs/current/00-README.md`——概览 + 导航：声明**选定基线**，并在中心位置说明验证信心约定，然后索引模块 / 主题文档。不要求逐模块状态汇总；链接出去。它链接到 PRD 封面 `../product/00-README.md`。
- 模块文档——按需每个模块一份；记录实际能力、关键行为与限制。声明继承概览的基线与信心；仅当模块确实基于不同基线时才覆写。
- 可选主题文档——跨切面领域（例如运维、数据）仅在需要时添加。
- 分层为概览 → 模块 → 可选主题。只添加项目实际拥有的内容；没有固定 schema。

Current 树**不按 PRD 编号**：模块可按名称对齐，但没有文件 / 段落镜像。显式链接 PRD 模块 / FR，多对多。

## 谁写

- **编码 agent** 在 issue 收尾时按选定基线更新 Current 事实。
- **编排者**评审 Current diff。
- 任何人都不在这里写任务历史、待办或计划工作。

## Current 文档记录什么

- **基线**——**选定**的基线：具体 revision / release 加快照日期。项目显式选择；若未选，询问用户——绝不默默默认 `main` 或最新 release。可变分支名本身不是快照 id；固定到 revision 或 release。
- **实际能力**——现在能做什么，用行为术语。
- **限制与已知约束**——什么不能做、缺点、边界、注意事项。
- **验证信心**——结论如何建立（已测试 / 已观察 / 推断）。在概览中集中声明口径；只在重要处逐条标注信心（例外），不必每条重复。

不要记录：任务日志、待办、计划 / 未来能力、逐 issue 进展。那些在 `docs/issues/` 与 PRD。issue 收尾**就地**更新受影响的 Current **事实**；绝不插入指向 issue 的自链接或任务历史。

## 同步

- Current 跟随**选定基线**：只记录已包含在该基线中的变更。基线前移时刷新受影响的 Current 文档；未进入选定基线的变更还不算 Current。实际状态未变 → 不改。
- issue 收尾**检查**完成的变更是否包含在选定基线内：是 → 更新受影响的 Current 文档；否 → 保持原样，在 issue 记录待同步项。
- 没有自动写入 Current 的自动化或钩子。同步是评审步骤，不是生成产物。

## 与 PRD / SPEC 的关系

- PRD = 宏观目标叙事；SPEC = 实现事实标准；Current = 实际建成。PRD 与 Current 是两棵独立、用户可读的树；互不内嵌，PRD 不是事实源。
- 两棵树之间**语义 / 导航 / 契约链接**是预期之内的——写普通相对 Markdown 链接；没有文件 / 段落镜像。
- Current 可链接 PRD、SPEC 或 ADR。PRD 不得链接 Current（也不得链接 SPEC 或 ADR）。
- Current 文档可用**描述性短语 + 稳定路径链接**指向 ADR（例：`支持[离线使用](../../adr/0003-offline.md)`）；描述独立撰写，不转述 ADR 理由。ADR 链接可选，方案绝不自动推断（见 `rendering.md`）。
- 差距比较读 SPEC 与 Current，产出供用户挑选的**候选**任务——不是每个差异都是缺失功能。差异可能是漂移、质量缺口、未验证行为或目标过时。已达成的粗目标仍可细化；不要凭空造差距。

## 接入（现有项目）

- 现有文档绝不覆盖或移动。v4 `docs/prd/` 树、PRD 中嵌入的现状 / 进展章节（例如每模块 `04-current.md`、`当前进展` 章节）或改名前的 `docs/pdr/` 树都是信息性遗留漂移——由 init 检测，绝不移动、改写或删除（`migration.md`）。
- 迁移到独立 Current 树，或从 v4 迁到 v5，都是显式的用户决策；没有自动移动。
