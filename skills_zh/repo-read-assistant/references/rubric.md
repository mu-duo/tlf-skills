# 评分标准

层级由证据决定，绝不凭印象。如果你无法引用用户说过或做过什么，层级就是 `L0`。

## 如何评 L0-L4

| 层级 | 名称 | 所需证据 | 典型失败 |
| --- | --- | --- | --- |
| L0 | unknown | 没有正确陈述；或没有记录任何观察 | 自信流畅的总结，但没有锚点 |
| L1 | locate | 给定功能或术语，无需帮助就能指出正确的文件 | 路径对，符号错 |
| L2 | explain | 未经提示，以正确的关系描述代码做什么以及为什么 | 事实对，关系错或反 |
| L3 | predict | 在看到结果之前说出接下来会发生什么或什么会坏；且正确 | 预测跟在揭示之后 |
| L4 | apply | 规划正确的改动：文件、调用点、测试、影响范围 | 说出文件但漏掉消费者或测试 |

评分规则：

- **一个概念一个层级。** 一个在回路上评为 L3、在重试上评为 L1 的概念，今天就是 L1，先前的分数作为证据保留。
- **顺序和关系胜过词汇。** 打乱顺序背诵名字，或把错误的两者连起来，至多是 L1-L2。
- **连贯性上限为 L2。** 正确但不连贯的模型——事实对、关系错——不能是 L3，无论它背出多少事实。预测需要可用的因果模型；箭头错了，预测就是运气。
- **锚点胜过文字。** 没有可定位锚点的正确解释，上限为 L2。
- **预测发生在阅读之后。** 用户先读 brief，然后预测改动的影响。L3 在那里评定，而不是在模型尚不存在时先猜一次。在看到答案之后作出的预测不算证据。
- **应用必须包含影响范围。** 说出被修改的文件只是 L3 级别的记忆；L4 要求说出后果。

## 证据记录

存储观察，而不是标签。没有证据的层级无法重新评级，下一个 agent 会继承一个它无法信任的断言。

好：

```yaml
- id: core-loop
  canonical: core task lifecycle
  anchor: 00-model.md#3-core-loop
  level: L2
  confidence: 0.8
  accuracy: 0.6
  evidence:
    - "On the model check, listed intake -> validate -> persist -> notify correctly, but put notify before persist."
    - "Predicted changing the validator would only affect intake; missed that the notifier reads its output at src/notify.ts:88."
  misconceptions:
    - "Notification runs before persistence."
  next_review: 2026-11-01
```

差：

```yaml
- id: core-loop
  level: L2
  notes: "User understands the flow."
```

差记录没有锚点、没有引用的回答、没有具体错误、没有日期。它无法驱动 drill，也无法被纠正。

更多差模式：

| 模式 | 为何失败 |
| --- | --- |
| `level: L3`，证据是「回答得很好」 | 没有预测内容；无法验证 |
| 证据是 agent 的解释 | 衡量的是 agent，不是用户 |
| 「已掌握」 | 是判定，不是观察 |
| 一条记录里塞五个概念 | 无法分别评级或排期 |
| 引用「架构 brief」却不给章节 | 之后无法定位纠正点 |

## 置信度与准确度

两者都是 `[0, 1]` 区间的数字。

- `confidence` — 直接问：「你有多确定，0 到 1？」记录他们说的数字。
- `accuracy` — 给回答打分：正确、有序、关系正确 = 1.0；正确但有一处关系断裂 = 0.5；错误 = 0.0。对该概念的各次观察取平均。

校准：

```
calibration_error = confidence - accuracy
```

| 值 | 解读 | 行动 |
| --- | --- | --- |
| `> 0.3` | 过度自信 | 先 drill。不要在该概念上推进到下一份 brief。 |
| `0.1 .. 0.3` | 略微过度自信 | 下次会话做一次模型检查。 |
| `-0.1 .. 0.1` | 已校准 | 正常间隔。 |
| `< -0.1` | 信心不足 | 说出来；用户知道的比自己以为的多。 |

过度自信优先。信心不足的用户会求助；过度自信的用户会重构核心回路。

按概念报告校准，绝不要用整个会话的平均值。一个坏概念会藏在一个好平均值里。

## 复习排期

根据评分后的层级设置 `next_review`：

| 层级 | 间隔 | 理由 |
| --- | --- | --- |
| L0 | 1 天 | 尚无可拉开的间隔；先重建锚点 |
| L1 | 1 天 | 不使用的话，定位能力衰减很快 |
| L2 | 3 天 | 解释需要一次巩固 |
| L3 | 7 天 | 预测更稳定，但仍脆弱 |
| L4 | 21 天 | 应用能力可迁移；偶尔检查 |

规则：

- 复习失败则层级降一，间隔重置为新层级对应的值。
- L3 或 L4 的复习通过可以一次性延长一档超出表格（L3 到 14 天，L4 到 30 天）；不要连续延长。
- `drill` 选择 `next_review <= today` 的概念，按 `calibration_error` 降序，再按最久未复习排序。
- 一次 drill 会话最多 12 个概念。疲劳会产生假阴性，假阴性会污染 profile。

## 会话级评分

会话结束时记录：

- 写就或纠正的 brief，及其章节级改动。
- 触及的概念及其层级变化。
- 发现的最强误解，逐字记录，以及在哪个章节被纠正。
- brief 的完成测试是否通过（`references/curriculum.md`）。
- 一句话说明下次会话从哪份 brief 开始。

一次既无层级变化、也无误解记录的会话，通常是 agent 在讲课、或用户只是点头的会话。在记录中说明这一点。
