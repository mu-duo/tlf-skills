# Current 现状文档

Current = 产品**当前实际建成**的样子：实际能力、关键行为与限制，每项都相对项目指定的基线陈述。它是 L3 层——实际建成快照——与 L1（人类目标叙事）和 L2（规范目标规格，唯一事实源）并列。它是与 PRD 平级的文档树（`prd.md`），不是 PRD 的一个章节。默认方案；可在项目副本中覆盖。Current 与 PRD 树及完整 ADR 集一起处于默认渲染范围内（`rendering.md`）。

**L1 是唯一不含状态的层；Current 是唯一的状态来源。** L1 叙述目标，不承载进展、状态标记或实际建成结论。实际现在能做什么，都在这里读。

## 结构

- `docs/current/00-README.md`——概览 + 导航：声明**选定基线**，并集中声明验证信心口径，然后索引模块 / 主题文档。不要求逐模块汇总状态；用链接引出。
- 模块文档——按需每模块一份；分别记录实际能力、关键行为与限制。各项结论继承概览的基线与信心；仅当模块文档基线确实不同时才覆写。
- 可选主题文档——跨领域方面（例如运维、数据），仅在需要时添加。
- 分层为概览 → 模块 → 可选主题。只添加项目实际具备的内容；没有固定 schema。

Current 树**不按 PRD 编号**：模块可以按名称对齐，但不做文件/段落镜像。显式地以多对多方式链接 PRD 模块 / FR。

## Current 文档记录什么

- **基线**——**选定的**基线：具体 revision / release 加快照日期。项目须显式选定；若未选定，询问用户——绝不静默默认取 `main` 或最新 release。单独一个会移动的分支名不是快照标识；要固定到 revision 或 release。
- **实际能力**——当前可用的功能，以行为描述。
- **限制与已知约束**——不可用之处、不足、边界、注意事项。
- **验证信心**——结论是如何确立的（已测试 / 已观察 / 已推断）。在概览中集中声明口径；仅在重要处（例外）逐条标注信心，不要对每条结论重复标注。

不要记录：任务日志、待办、计划中 / 未来的能力、逐 issue 进展。这些位于 `docs/issues/` 和 PRD。issue 收尾就地更新受影响的 Current **事实**；绝不插入指向 issue 的自链接或任务历史。

## 同步

- Current 跟随**选定基线**：只记录已包含在该基线内的变更。基线前移时刷新受影响的 Current 文档；未包含在选定基线内的变更尚不属于 Current。实际状态未变 → 不修改。
- issue 收尾**检查**已完成的变更是否包含在选定基线内：是 → 更新受影响的 Current 文档；否 → 保持不动，并在 issue 中记录待同步项。
- 没有自动写入 Current 的自动化或钩子。同步是一个评审步骤，不是生成的产物。

## 与 PRD 的关系

- L2 = 规范目标（`prd.md`）；L1 = L2 的人类叙事视图；Current = 实际建成形态。L1 与 Current 是两棵独立、用户可读的文档树；互不内嵌，L1 不是事实源。
- 两树之间的**语义 / 导航 / 契约链接**是预期之中的——写普通相对 Markdown 链接；不做文件/段落镜像。
- Current 可以链接到 L1、L2 或 ADR；L1 不得链接到 Current（也不得链接到 L2 或 ADR）。
- Current 文档可以用**描述性短语 + 稳定路径链接**指向 ADR（例如 `支持[离线使用](../../adr/0003-offline.md)`）；描述独立撰写，不转述 ADR 理由。ADR 链接可选，本方案绝不自动推断（见 `rendering.md`）。
- 差距比较会读取 L2 与 Current，并产出**候选**任务供用户选择——不是每个差异都代表缺失功能。差异可能是漂移、质量差距、未验证行为，或目标过时。已满足的粗粒度目标仍可细化；不要臆造差距。

## 接入（现有项目）

- 现有文档绝不覆盖或移动。如果项目此前在 PRD 内嵌入了 current/progress 材料（例如每模块的 `04-current.md`、`当前进展` 章节），init 会将这些路径作为信息性**遗留漂移**报告。重命名前的 `docs/pdr/` 树同样属于信息性遗留漂移——init 绝不移动、改写或删除。
- 迁移到独立的 Current 树，或从遗留 `docs/pdr/` 迁移到 `docs/prd/`，都是用户的显式决定；没有安装迁移脚本，也不会自动移动。
