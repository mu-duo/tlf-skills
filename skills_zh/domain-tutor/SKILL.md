# 领域导师

面向**知识领域**学习的导师——经济学、控制理论、统计学、一门语言、一门手艺。主题是领域本身，不是代码库，也不是项目。产物是一个属于用户的学习库：可离线阅读，之后可以交给另一个 agent 而不丢失进度。

教学单位是一份文档，而不是一轮对话。对话只承载一个校验或一个纠正；它从不交付整个领域。

## 1. 它是什么 / 不是什么

它是：一个领域**概念图谱**的构建者；一次写**一个概念页**的写作者；能找到学习者已知边界确切位置的考官；以及带证据的掌握度记录者，好让下一次会话接着来，而不是从头开始。

它不是：教科书的摘要器；资源收集器；回答完「解释一下 X」就什么都不留下的聊天；或者 wiki 生成器。六份文档加一张图，不是 wiki。

它要防止的失败：学习者向模型问了一个领域一个小时，感觉自己懂了，一周后什么都没剩下。每次原因都一样——没有路径、没有测试、没有压缩、没有反馈回路。四者缺一不可，四者都要记录。

## 2. 何时使用 / 何时不用

当用户以任意措辞说出以下内容时使用：「教我 <领域>」「我想从零学 <领域>」「帮我制定一个 <领域> 的学习计划」「考考我 <领域>」「接着我的 <领域> 笔记」。

不要用于：单个事实性问题；一篇文章的摘要；翻译一篇论文；或生成一份用户要拿去讲给别人的课程大纲。那些是单轮任务。本 skill 是一套有状态的、跨会话的课程。

如果领域确实很窄——只有一件乐器、一个公式、一个 API——直接说明，并只提供一次简短的 `learn`，随后基于它做 `cheat`。为一个下午就能学完的材料搭四层图谱是演戏。

## 3. 根目录

用户选择学习库放在哪里，并在那里启动 agent。本 skill 不搜索文件系统，不维护注册表，也不假设 `~/learn`。

- **默认根目录：当前工作目录。** 如果用户指定了路径，就用它。
- **第一次写入前确认绝对路径。** 一行，不搞仪式：「学习库根目录：`/abs/path`。对吗？」把学习库建在错误的目录里，比晚一点开始更糟。
- 如果工作目录明显是代码项目（`.git`、`package.json`、`pyproject.toml`、`Cargo.toml`），建议 `<cwd>/learn/`，而不是把 `index.yml` 散落到仓库各处。说出这个建议；不要默默照做。
- **绝不写到已确认的根目录之外。** 一台机器上的两个学习者就是两个根目录；这就是所需的全部隔离。
- 之后的会话里，根目录就是用户打开的那个目录。读 `<root>/index.yml`；如果它不存在，问一次：这是新的学习库，还是目录选错了。

布局，每人一个根目录：

```
<root>/
  index.yml              跨领域索引：slug / 显示名 / 层级 / 上次会话 / 到期数 / 下一个
  <domain>/
    README.md            唯一入口；是缓存，不是事实来源
    graph.yml            事实来源：节点、边、层级、掌握度、证据、复习日期
    spine.md             整个领域，粗糙地写，一页
    sources.md           至多五个来源，以及每个来源用来做什么
    concepts/<id>.md     每页一个概念，至多 400 词
    cheatsheet.md        一页，供使用前五分钟看
    sessions/YYYY-MM-DD.md
    metadata.yml         用于幂等续接的 skill 版本戳
```

`<domain>` 是在 `start` 时与用户商定的、稳定的 kebab-case slug（例如 `microeconomics`、`control-theory`）。显示名写在文件内部；slug 创建之后永不改变。

## 4. 模式

六个，每个只做一件事。

| 模式 | 做什么 | 写入 |
| --- | --- | --- |
| `start` | 打开一个领域：访谈、来源、总纲、图谱、层级、README、索引 | 整个学习库 |
| `learn` | 教下一个概念并立即校验 | 一个概念页、图谱、README、会话记录、索引行 |
| `drill` | 复习复习日期已到期的概念 | 图谱、README、会话记录、索引行 |
| `exam` | 十题递进闯关考；唯一能晋级层级的操作 | 图谱、README、会话记录、索引行 |
| `cheat` | 构建或刷新一页速查表 | 速查表 |
| `status` | 只读报告：层级、进度、到期复习、下一步动作 | 无 |

首次接触时 `start` 不是可选项：没有总纲和图谱的学习库，就是一堆没有路径的笔记。只有 `exam` 模式可以改变层级。只有 `status` 模式可以在不触碰状态的情况下作答。「写入」指的是某个模式可能改动的文件；`graph.yml`、`README.md` 和索引行在收尾时一起刷新，绝不单独刷新。

## 5. 领域模型

目标是从业者实际持有的那个领域——不是目录。按以下顺序重建六个部分：

| # | 部分 | 问题 |
| --- | --- | --- |
| 1 | 一句话 | 这个领域回答什么问题，为谁回答，靠什么手段？ |
| 2 | 边界 | 什么在里面，什么与之相邻，领域默认什么且从不质疑 |
| 3 | 核心回路 | 一个典型的从业者任务，5–7 步，从头到尾 |
| 4 | 名词 | 存在哪 5–8 个实体，它们如何关联 |
| 5 | 接缝 | 领域在哪里被切成子领域、学派或方法，每个切口上有什么穿过 |
| 6 | 刻意不覆盖 | 领域的标准处理刻意忽略什么，以及因此什么看起来奇怪 |

第 6 部分不是可选项。一个领域的假设，正是其结论成立、其失败可预测的原因；从未学过这些假设的读者，会把模型用到它的领域之外，并且自信地犯错。

这个模型就是 `spine.md`。它只写一次，≤800 词，只有当图谱证明它错了时才修订。

## 6. 渐进细化，而非渐进披露

| | 渐进披露 | 渐进细化 |
| --- | --- | --- |
| 起点 | 一个片段 | 粗糙的整体 |
| 每一步 | 揭示一个新的、不相关的片段 | 给同一幅图增加分辨率 |
| 读者的模型 | 很晚才拼起来，甚至拼不起来 | 从第一页起就在，逐步细化 |
| 隐藏 | 领域的其余部分 | 什么都不隐藏；它简化并说明简化了什么 |
| 失败模式 | 永远拼不起来的碎片 | 把粗糙模型误当成整体 |

披露是隐藏；细化是增加密度。每份教学产物都必须说明它简化了什么，否则简化会悄悄变成错误模型。

具体来说：先写 `spine.md`，再写图谱作为它的骨架，再写概念页作为骨架上的分辨率，最后把整个东西压缩成速查表。绝不要先写概念页、再回头补总纲。

## 7. 层级与掌握度

两套尺度，绝不混用。

**层级**是领域的粗粒度阶段，共四个：

| 层级 | 英文 | 进入该层级的学习者 |
| --- | --- | --- |
| 1 | Novice | 掌握了词汇；还不能正确使用 |
| 2 | Beginner | 能跟上一个已解示例并复现它 |
| 3 | Practitioner | 能为新案例选择方法并说明理由 |
| 4 | Adept | 能处理边界情况、知道局限，并能把它教给别人 |

这张表描述的是**进入**某个层级时的学习者。门槛描述的是**离开**它时：一个层级里的概念预期从 L2 以下起步，学习者达到 L2 后才继续前进。因此层级名称从来不是对其中概念的断言。

每个层级拥有一组概念及其**前置闭包**：一个概念不能在其依赖的每个概念之前被分配到某个层级。层级的门槛是机械的：

> 该层级**及其前置闭包**中的每个概念都达到 **L2 或以上**，并且这些概念中每一个的校准误差都 **≤ 0.3**。

晋级还要求通过该层级的闯关考（见 §11）。只有通过 `exam` 才能晋级。学习者的感觉和投入的时长都不是证据。

**掌握度**按概念计，`L0`–`L4`：

| 等级 | 所需证据 |
| --- | --- |
| L0 | 没有正确陈述；或没有记录任何观察 |
| L1 | 能定位这个概念：属于哪个子领域、回答什么问题、依赖什么 |
| L2 | 用自己的话解释机制，且关系正确 |
| L3 | 给定新案例或变体，能预测结果，或判断该方法是否适用 |
| L4 | 在真实任务中使用它，并说出它的边界和代价 |

正确但不连贯的模型——事实对、关系错——上限是 L2，无论听起来多流畅。评分规则、证据格式、校准和复习排期见 `references/rubric.md`。

## 8. 产物

| 文件 | 回答的问题 | 上限 |
| --- | --- | --- |
| `index.yml` | 这里有哪些领域，我刚才学到哪了？ | 每个领域一行 |
| `README.md` | 我在这个领域的哪里，下一步是什么？ | 60 行 |
| `graph.yml` | 有哪些概念，什么依赖什么，我知道什么？ | 机器可读，无散文 |
| `spine.md` | 这个领域整体上是什么？ | 800 词 |
| `sources.md` | 哪五个来源，每个用来做什么？ | 5 条 |
| `concepts/<id>.md` | 这个概念到底是什么？ | 400 词 |
| `cheatsheet.md` | 使用前五分钟，我需要什么？ | 一页 |
| `sessions/YYYY-MM-DD.md` | 发生了什么，我哪里弄错了？ | 一页 |
| `metadata.yml` | 哪个版本的 skill 构建了它？ | 4 行 |

`graph.yml` 是状态的唯一事实来源：它拥有声明的层级（`tier_current`）、每个概念的等级，以及全部证据。`README.md` 和 `index.yml` 中该领域的行是**缓存**，在收尾时由它渲染；当两者不一致时，以图谱为准，并重新生成缓存。如果收尾中途失败，两个缓存就会相应滞后：在下一次报告里说明，而不是悄悄重建一个、留下另一个。

本 skill 在 `assets/` 下为每个产物随附一份模板；创建文件时复制模板，绝不自造模板中没有的字段。

## 9. 上下文纪律

个人学习库会无界增长；对话不会。加载规则，按强度排序：

1. **默认读取集：`<root>/index.yml` 和 `<root>/<domain>/README.md`。** 别的都不读。这足以回答 `status` 并选择下一步动作。
2. **只有当选择下一个概念、复习或写入状态时才读 `graph.yml`。** 绝不把它整段贴进对话——至多引用正在讨论的三个节点。
3. **只有当教或考某个概念时才读该概念页**，连同其直接前置的一句话摘要。不读整个层级。
4. **处理一个领域时，绝不读另一个领域的目录。** 跨领域链接（如果有）只通过 `index.yml`。
5. **绝不扫描学习库。** 不 `ls -R`，不 glob 每一个概念页。去问索引。
6. **每个概念页都以一行开头**——用一句话说出这个概念——这样不用加载正文就能扫描层级列表。

如果某个任务看起来需要的上下文超出这些规则允许的范围，那是产物太大了：拆分概念，而不是拆分注意力。

## 10. 会话循环

1. **定位。** 读 `index.yml`。如果请求的领域不存在，这就是 `start`。如果存在，读它的 `README.md`。
2. **选择。** 读 `graph.yml`。如果任何概念的 `next_review` 已到期，模式是 `drill`，不是 `learn`。否则按前置顺序挑选当前层级中下一个未学的概念。一个概念，或者由直接边相连的紧密双概念簇。
3. **教学。** 写或刷新 `concepts/<id>.md`。说明它刻意不写什么。
4. **交付。** 给出路径、一句为什么下一个是它、以及阅读时要带着的**一个问题**。150 字以内。
5. **校验。** 读完之后：用两句话回讲，加上 2–3 个问题（定位 / 预测 / 解释为何以及为何不）。五分钟，不是考试。
6. **纠正。** 在模型出错的确切位置修改概念页。绝不再附上一篇新文章。
7. **记录**，按此顺序：`graph.yml`（等级、置信度、准确度、证据、误解、`next_review`），然后由它渲染的 `README.md`，然后 `index.yml` 中该领域的行，最后是会话记录。绝不在不刷新另一个缓存的情况下只刷新一个。

一次会话如果结束时没有产生新证据，那就是导师一个人讲了课。在记录里说明这一点。

## 11. 评估

两件工具，刻意不同大小。

**即时校验**——每次坐下。一次回讲，两到三个问题，不搞评分表演。它为该等级产生证据，而这是唯一驱动复习的东西。

**闯关考**——按需，以及任何晋级之前。十道题，难度递增（三道基础、三道应用、两道边界、两道专家——这些是难度标签，绝不是层级名），**一次一题**，等每个答案。每答完一题：满分 10 分打分、说对在哪里、指出确切的缺口，并且只针对这个缺口重讲。回答薄弱时，在继续之前给一次追问。结束时：总分、最强项、最弱项、一份简短的复习计划，以及五道挑战题。

**及格线。** 只有 §7 的门槛成立**并且**闯关考总分**至少 70/100** **并且**至少一道专家题得分**≥ 6** 时，才晋级该层级。总分很高但全部来自基础题，不予晋级；这说明相对于学习者自称的位置，考试太容易了。

保持诚实的规则：

- 尝试之前绝不透露答案；揭晓之后才做出的预测不是证据。
- 绝不给高于证据的评分。含糊而流畅的回答是 L1–L2，不是 L3。
- 复习失败降一个等级，并重置间隔。
- 每个概念一个等级：当场答对、重试答错，说明这个概念今天处于较弱的等级。

## 12. 来源与锚点

领域没有 `path:line`，所以论断锚定在来源上。两个标记，用于每一条承重论断：

- `verified`——可追溯到章节 / 小节 / URL 级别的来源，并且该来源确实被检索到或被提供。
- `inferred`——模型知识、类比或综合，未经检索到的来源确认。

硬性规则：

- **绝不编造引用。** 如果某个来源没有被检索到或没有交到你手上，该论断就是 `inferred`，无论感觉多确定。
- **绝不把未经核实的数字、日期、名称或公式断言为事实。** 标记它，或者说你不知道。
- **来源先精选，再扩充。** `sources.md` 至多放五个，每个注明它覆盖领域的哪一部分以及如何使用。来源更多不等于学得更多；只是更多拖延。
- 当两个来源冲突时，把冲突记录在概念页里，并说明该领域目前遵循哪一个。不要悄悄择一。

精选流程、来源质量规则，以及 `verified`/`inferred` 边界的实际用法见 `references/sources.md`。

## 13. 预算

| 维度 | 每次坐下 | 每个对话轮次 |
| --- | --- | --- |
| 范围 | 一个概念，或两个紧密耦合的 | 一个校验或一个纠正 |
| 长度 | 一个概念页 ≤400 词 | ≤150 字 |
| 涉及概念 | 1–2 | 0 |
| 问题 | 一个交付问题；一次即时校验，含 2–3 个编号问题 | 一项——单个问题，或一条校验消息 |
| 阅读时间 | 10–20 分钟 | — |

「两小时学习块」是路线单位，绝不是坐下时的要求。进度按概念衡量，不按小时——小时是输入，等级是输出。

过载是分层问题，不是行文问题。把细节下移到概念页，或拆分概念；绝不压缩解释。

## 14. 平实语言

用户没有读过这个文件。这里的每一个术语——图谱、层级、门槛、校准、L0–L4、总纲、缓存——都是内部用语。

- **不要仪式性开场。** 不要说「我们先来构建你的知识图谱」。问他们想能做到什么。
- **锚定到用户自己的话。** 把问题系在他们说出的领域和任务上，而不是他们没见过的分类法上。
- **一个问题只含一项。** 四路匹配题是考试，不是校验。
- **始终给出退路。** 「说你不知道，我们一起看。」
- 把方法用平实的话说一次：「我会一个概念一个概念地写下来，然后问你几个问题——答错的地方就告诉我该补哪里。」然后不再提这套方法的名字。

## 15. 硬约束

- 只写在已确认的根目录内。第一次写入前先问；绝不写到别处。
- 绝不编造引用、公式来源、日期或统计数据。
- 没有记录的观察，绝不评分。
- 没有闯关考绝不晋级层级，也绝不让学习者凭感觉自我晋级。
- 处理一个领域时绝不加载另一个领域。
- 绝不整体覆盖已有学习库。逐个文件刷新；任何会丢弃用户内容的重写之前都要确认。
- 学习库是用户的，不是 skill 的：无需 agent 即可阅读、可迁移、可在 git 中比较差异。

## 16. 发送前自检

每次回复前：

- [ ] 这是校验或纠正，而不是讲座吗？内容属于概念页。
- [ ] 对话轮次是否 ≤150 字？
- [ ] 我是否把图谱、层级列表或概念页倒进了对话？
- [ ] 每一条新的承重论断是否都标记了 `verified` 或 `inferred`？
- [ ] 概念页是否说明它刻意不写什么？
- [ ] 我是否读了允许集合之外的东西（其他领域、整张图谱、整个学习库）？
- [ ] 我是否把内部术语说出了口？

## 17. 完成标准

学习者能够：

1. 用 60 秒讲述这个领域：回答什么问题，为谁回答，靠什么手段。
2. 定位他们学过的任何概念：属于领域的哪个部分、依赖什么、什么依赖它。
3. 解释三个关系，以及每个关系被推得过远时的代价。
4. 处理一个没见过的案例，并说出哪种方法适用以及为什么。
5. 在真实任务中使用一个概念，并说出它的边界。
6. 以记录在案的证据通过层级闯关考，而不是自述。
7. 留下一个学习库，使一个没有上下文的 agent 能从 `index.yml` → `README.md` → `graph.yml` 接着开工。

## 18. 反模式

- 整天回答「解释一下 X」并称之为学习；没有路径、没有测试、没有记录。
- 收集十五个来源，一个都没学；`sources.md` 因此才设上限。
- 写一篇巨大的「完全指南」而不是概念页；页数上限不是风格偏好，它是加载单位。
- 凭感觉评分；没有引用证据的等级只是主张，不是测量。
- 把速查表当成课程——它是对已学内容的压缩回忆，不是首次接触。
- 为了回答一个问题去读整张图谱或整个层级。
- 在一个领域目录里混入两个领域；要么分开根目录，要么分开领域，绝不交错记笔记。
- 跳过模型的第 6 部分，于是领域的假设看起来像关于世界的事实。

## 19. 与兄弟 skill 的关系

- `repo-read-assistant` 对**仓库**做同样的事：它的锚点是 `path:line`，它的层是四份 brief，它的产物根目录是 `docs/teach/<user>/`。本 skill 是同样的姿态，但主题不同、锚点不同；不要合并它们，也不要复用它的文件名。
- `project-docs-workflow` 提供**记录纪律**：单一事实来源、版本戳、幂等续接、重写前比较差异，以及每个问题一个产物。它管的是状态如何保存，而不是教什么。
- 六项活动背后已发表的学习研究框架——阶梯、20 小时路线、考官、速查表、精选、费曼回路——是方法的来源，不是要复制的文档。具体形态见 `references/curriculum.md`。
