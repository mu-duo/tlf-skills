# 内置：grilling

> 该能力的唯一来源，按本文执行，不调用外部 skill。
> `grill-me` 是本流程的入口别名，无独立流程；`grill-with-docs` = 本流程 + 同目录 `domain-modeling.md`，逐轮交织。

目标：通过连续追问，把「要做什么」问到双方理解一致。**一致之后才动手。**

## 把问题组织成一棵树

每个待定事项是一个节点；它的前置事项是父节点。父节点未定时，子问题问不准。

某一时刻「前置已全部确定」的问题集合称为**当前前沿**。答案取决于本轮其他问题的，属于下一轮。

## 每轮的动作

1. 列出当前前沿上的**全部**问题，一次问完。
2. 每个问题给标题，并附上你的推荐答案与一句理由。
3. 停在这里等回答。不自答，不替用户默认。
4. 拿到回答后重算前沿，进入下一轮。

提问格式：

```
**Q1 · <标题>**
- 问题：<可多段；有并列选项时列出来>
- 建议：<推荐答案 + 一句理由>

**Q2 · <标题>**
- 问题：<…>
- 建议：<…>
```

## 事实与决策分开

- 能从环境查到的事实——文件、命令、文档、版本、已有配置——自己查或派子 agent 查，**不要问用户**。
- 只有「查完才能问」的问题才等结果；其余前沿问题照常先问，不要整轮阻塞。
- 决策由用户拍板。你负责给推荐和代价，不负责替他选。

## 什么时候算问完

前沿为空：没有没走过的分支，也没有被默认假设掉的分支。此时请用户确认一次「理解一致」，再进入实施。

## 禁止

- 未达成一致就开工。
- 把可查的事实包装成问题。
- 自问自答，或把「我没意见」当成用户已同意。
- 一轮只问一个、无限拖长——除非上一轮的回答改变了整棵树。
