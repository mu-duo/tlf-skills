# 文档 HTML 渲染（docs-html-view）

默认方案；项目可在物化副本中覆盖。

渲染是由第一方 `docs-html-view` skill 在本方案之外提供的**可选的、用户触发**的能力。本方案只固定渲染所依赖的**文档契约**：渲染什么、如何撰写链接，以及源文件永不改写。它绝不安装、构建、渲染或激活任何东西，init 也不创建任何渲染器产物。

## 默认渲染范围（完整站点）

- **范围内**：`docs/prd/`、`docs/current/`，以及**完整**的 `docs/adr/`——包含退役条目与墓碑桩，并保持其退役标记（`> 已废弃…` / `> 已删除…`）可见，使退役决策仍可导航。
- **范围外**：`docs/issues/`、`docs/agents/`——工作材料，不是发布文档。
- **产品 L1 是完整站点中的显眼入口**：产品 `docs/prd/00-README.md` 作为指定的「产品概览」入口（通过渲染器的 `landing_page` 配置），显眼地链接在 toctree 之上，使读者从叙事开始。
- **`00-index.md` 是次级入口**——它渲染为模块导航与追溯，而不是首读内容。
- 项目可以覆盖该范围。

## L1 专用渲染

- **范围内**：产品 L1（`docs/prd/00-README.md`）加每个模块 L1（`docs/prd/<NN-模块>/00-README.md`）——仅此而已。
- **范围外**：L2（`01-spec` / `02-interfaces` / `03-nfr` / `design/`）、Current、ADR，以及 `00-index.md`。
- 输出是一个自包含目录，可打包成 zip 分发给只需要产品叙事的读者。
- 由于 L1 不得向外链接，L1 专用构建没有需要解析的外部目标；只有内部锚点需要注意。

## 链接撰写

- **L1 链接**：仅限内部——同文件锚点、产品 L1 ↔ 模块 L1、模块 L1 ↔ 模块 L1。锚点目标是标准 Markdown 标题，h1–h3。不得有外部链接（`http` / `https` / `mailto`），也不得链接到 L2、Current 或 ADR；这些放在 `00-index.md`。
- **PRD ↔ Current**：两树之间的语义 / 导航 / 契约链接是预期之中的（`prd.md`、`current.md`）。写普通相对 Markdown 链接，使源文件与渲染结果都能导航。
- **PRD / Current → ADR**：用**描述性短语 + 稳定路径链接**指向 ADR 文件，例如 `支持 [离线使用](../../adr/0003-offline.md)`。描述独立撰写、自足成立；**不**转述或概括 ADR 的理由。不要求每条需求都挂 ADR，本方案绝不自动推断 ADR 链接。该规则适用于 L2 与 Current，**不**适用于 L1。
- 原生 `ADR-XXXX` 引用写法不变；ADR 删除 / 语义修改会核查**两种**写法（`adr.md`）。

## 源文件永不改写

- Markdown 源文件保持单一事实源地位，本身仍可人工阅读；渲染器对它们**只读**——不规范化、不移动、不改写。
- 范围外或悬空的引用会被**报告**，绝不在源文件中修复。
- 「无可渲染内容」是一种**失败**，而不是静默成功；渲染器绝不自行引导文档工作流。

## 手动、选择启用

- 渲染**由用户触发且手动**：没有钩子，文档编辑时不自动构建，不为创建渲染器而改动主要 init 产物。
- 仅在通过 skill 交互获得用户显式同意后，才安装 / 初始化 / 首次构建；没有自定义编排器、manifest 或审批状态机。
- 要集成时，显式让项目指向 `docs-html-view` skill；不要把它接入初始化流程。
