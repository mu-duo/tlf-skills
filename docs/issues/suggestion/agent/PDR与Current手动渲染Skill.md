## 背景

PDR 与 Current 是彼此独立、用户可读的文档树（形态决定见 [模糊PDR与探索式开发模型](模糊PDR与探索式开发模型.md)）。在阅读 Markdown 之外，用户可能希望有渲染后的形式。本条目记录一个候选方向：把渲染打包成一个 skill。

本条目为 `suggestion`（无状态、无 history），归宿是 ADR / PDR / 删除。已确认的是使用边界（见下）；实现本身未获批准——本条目不授权创建任何渲染 skill。

## 已确认的使用边界

- 用户触发：渲染由用户显式触发；对 PDR 与 Current 两套独立文档都适用。
- 源保持可读：源文档须人类可读且渲染友好；不要求源改用某种新的具体格式（格式与工具留待后续）。
- 工具不固定：不绑定具体工具（Sphinx 仅作示例）。
- 绝不自动：日常文档编辑时，绝不自动安装 / 构建 / 渲染。
- 尊重项目覆盖：具体工具 / 格式由项目决定，默认值可被项目覆盖。

## 未批准 / 待讨论

- 渲染的实现未获批准：本候选不授权实现渲染。
- 这不影响本轮并行批准的 workflow 拆分（见 [拆分Current与精简任务日志](../../feature/history/拆分Current与精简任务日志-done.md)）；仅指不在本候选下做任何渲染实现。
- 待定：工具选型、输出格式、导航、交叉链接、产物管理、打包方式（独立 skill / 集成进 `project-docs-workflow` / 混合）。
