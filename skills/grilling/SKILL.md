# Grilling（追问式访谈）

> 轻量精简版，裁剪自 [mattpocock/skills](https://github.com/mattpocock/skills) 的 grilling（MIT License, Copyright (c) 2026 Matt Pocock）。若环境已安装同名完整 skill，请优先使用完整版。

持续追问用户，直到双方对方案达成共同理解。把这次访谈建模成一棵**设计树（design tree）**：每个决策都会分叉出依赖它的子决策。

## 按轮次推进

**frontier（前沿）** = 所有前置条件已确定的决策：也就是你现在就能问、不必臆测尚未听到的答案的问题。

1. 一轮处理当前 frontier：把 frontier 上的问题**一次性全部提出**。
2. 每个问题**编号**，并给出**你推荐的答案**。
3. 等用户回答后，再进入下一轮。

轮次格式：

```
❓ **Q1** - **<问题标题>**：<问题正文，可多段，可含多选项>

➡️ <你推荐的答案>

---

❓ **Q2** - **<问题标题>**：<问题正文>

➡️ <你推荐的答案>
```

用户每一轮的回答会重塑整棵树：已确定的决策把 frontier 向外推，解锁依赖它们的问题。每轮结束都**重新计算 frontier**，再问下一轮。若某问题的答案依赖本轮尚未解决的另一个问题，它属于**后面的轮次**，不属于本轮。

## 事实 vs 决策

- **事实是 agent 的活，永远不要问用户。** 当某个 frontier 问题需要环境中的事实（文件系统、工具、外部文档等），派子 agent 去查，不要问用户你本可以自己查的东西。
- **不要因此阻塞**：一个还在跑的探查本身就是一个未确定的前置条件，所以只有它下游的问题需要等子 agent 回报；frontier 上其余问题现在就问。
- **决策是用户的活。** 每个决策都摆到用户面前并等待回答，绝不替用户拍板。

## 完成条件

当 frontier 为空——设计树每个分支都走过、没有任何东西被默默假设——本次访谈结束。

**在用户确认你们达成了共同理解之前，不要动手实施。**
